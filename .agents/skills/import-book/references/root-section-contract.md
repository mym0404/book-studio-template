# 루트 섹션 작업 계약

루트 에이전트가 섹션을 하나씩 작성하고 검증한다. 한 섹션의 `Result: PASS`를 기록한 뒤 다음 섹션으로 이동한다.

## 작업 입력

- 원본 PDF 절대경로와 물리 페이지 범위
- Docling Markdown·JSON·artifact bundle 경로
- 장·절 제목과 앞뒤 경계
- 본문 모드와 MDX 모드로 구성된 충실도 계약
- 책별 표현 카탈로그 경로
- 담당 섹션에만 쓰는 fragment 경로
- 담당 섹션에만 쓰는 원문 추적표 경로
- 저장소의 두 knowledge 문서와 사용 가능한 PDF 스킬

## 섹션 처리

1. `mise exec -- uv run .agents/skills/import-book/scripts/pdf_tool.py render /absolute/path/to/book.pdf --pages 1,3-5 --output-dir /absolute/path/to/rendered-pages`로 담당 PDF 페이지를 PNG로 렌더링하고 Docling 텍스트·JSON bbox를 보조 단서로 사용한다.
2. 시각적 읽기 순서대로 heading, 문단, 목록, 인용, 각주, 코드, 수식, 표, figure, 캡션과 특수 표현을 식별한다.
3. 선택한 충실도 계약과 표현 카탈로그를 적용해 fragment를 작성한다.
4. 코드 이미지는 PDF를 보며 줄별로 전사하고 언어 fence를 지정한다.
5. fragment를 PDF와 다시 대조하고 원문 추적표를 작성한다.
6. 임시 렌더를 삭제하고 `Result: PASS`인 fragment와 원문 추적표를 확정한다.

## 원문 추적표

| ID | PDF 물리 페이지 | 원문 블록 | 결과 블록 | 처리 | 카탈로그 ID | 검증 |
| --- | --- | --- | --- | --- | --- | --- |

- `처리`는 `유지`, `번역`, `통합`, `삭제`, `구조 이동` 중 하나다.
- 원문 보존·완전 번역에서는 모든 콘텐츠 블록을 기록하고 처리를 `유지`, `번역`, `구조 이동`으로 제한한다.
- 압축 정리·핵심 요약에서는 `통합`, `삭제`의 충실도 근거를 적는다.
- 특수 표현은 `카탈로그 ID`에 연결한다.
- 코드에는 줄별 대조 결과, figure에는 이미지·캡션 대조 결과를 적는다.

## PASS 기준

- 담당 범위의 모든 콘텐츠 블록이 원문 추적표에 정확히 한 번 나타난다.
- 결과의 모든 문장·코드·표 셀·이미지·강조가 원문 블록에 연결된다.
- 모든 특수 표현이 카탈로그 ID와 표준 MDX에 일치한다.
- 원문 보존 모드에서 정규화한 prose와 heading 토큰의 누락·추가·순서 차이가 0건이다.
- 코드의 OCR 오자, 합쳐진 산문, 중복 캡션과 원문에 없는 줄이 0건이다.
- fragment는 섹션 본문만 포함한다.

모든 기준을 확인한 뒤 원문 추적표 마지막 줄에 `Result: PASS`를 쓴다. 확인하지 못한 기준이 있으면 `Result: FAIL`과 정확한 차이를 기록하고 같은 섹션에서 수정과 대조를 반복한다.

## 조립과 전체 대조

- 루트 에이전트가 PASS fragment의 본문을 byte-for-byte로 원문 순서대로 연결한다.
- 충실도 계약에 따라 원문에 연결되는 frontmatter, 필요한 MDX import, asset 경로, book metadata와 목차 링크를 작성한다.
- 원본 PDF, 최종 MDX와 표현 카탈로그를 처음부터 다시 대조한다.
- prose·heading·캡션은 전체 정규화 비교하고 코드는 PDF 렌더와 줄별로 비교한다.
- figure·특수 표현·표·수식·각주 수와 배치 근거를 확인한다.
- 모든 PASS 기준과 카탈로그 일관성 검사를 통과하면 `Result: PASS`를 기록한다.
