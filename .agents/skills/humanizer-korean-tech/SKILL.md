# Humanizer Korean Tech

한국어 문장을 자연스럽게 다듬되 원문의 사실과 구조를 보존한다. 기본 모드는 확실한 문제만 빠르게 고치고, 강한 모드는 문장별 검사와 문서 전체 반복 검사를 추가한다.

명령 예시에서는 현재 읽은 `SKILL.md`가 있는 디렉터리의 절대경로를 `SKILL_DIR`로 사용한다.

## 모드 선택

- 별도 지시가 없으면 `기본` 모드를 사용한다.
- 사용자가 `강하게 검사`, `철저히 검사`, `전수 검사`, `hard mode`, `모드: 강함`을 명시하면 `강함` 모드를 사용한다.
- `강함`에서만 `$SKILL_DIR/references/hard-rules.md`를 전체 읽는다.

## 대상 결정

- 사용자가 붙여넣은 글은 응답에서 바로 고친다.
- 사용자가 파일 수정을 맡기면 해당 파일의 한국어 문구를 직접 고친다.
- 다른 작업에서 만든 산출물에 이 스킬을 적용하라고 하면 그 산출물을 직접 고친다.
- UI·소스 파일에서는 사용자에게 보이는 한국어 문자열만 고치고 코드, 식별자, 마크업 구조는 유지한다.
- 별도 `final.md`나 임시 결과 경로를 사용자에게 강요하지 않는다.

## 공통 규칙

두 모드에서 항상 적용한다. 확실하게 고칠 수 있는 문제만 다루고, 문맥에 따라 뜻이 갈리면 원문을 유지한다.

### 보호 범위

- 사람·지역·기관·브랜드·제품·모델 이름을 보존한다.
- 수치·날짜·단위·금액을 보존한다.
- 직접 인용과 법령 조문을 보존한다.
- 코드·식별자·명령어·URL·Markdown 링크·영어 약어를 보존한다.
- 사실·주장·인과관계·결론·문장 수·순서를 보존한다.
- 헤딩·목록·표·코드 블록과 주변 파일 구조를 보존한다.
- 기술 문서에서는 공식 표기를 유지하고 같은 개념에 같은 용어를 쓴다.

### 맞춤법과 띄어쓰기

- 정답이 분명한 오타를 고친다: `됬다→됐다`, `몇일→며칠`, `역활→역할`, `오랫만→오랜만`, `희안하다→희한하다`, `금새→금세`, `왠만하다→웬만하다`.
- 받침이 없으면 `예요`, 받침이 있으면 `이에요`를 쓴다. `아니에요`는 그대로 쓴다.
- 약속 종결은 `-ㄹ게`, 의도는 `-려고`로 쓴다.
- `어떻게`와 `어떡해`, `율`과 `률`, `낫다`와 `낳다`처럼 답이 분명한 혼동을 고친다.
- 조사는 앞말에 붙이고 의존 명사 `것·수·데·지`는 띄운다.
- 수와 단위, 이름과 호칭은 띄어 쓴다: `한 개`, `두 살`, `홍길동 씨`.
- 금지·부정의 `안 되다`는 띄어 쓴다.
- 불필요한 접속사 뒤 쉼표와 중복 마침표를 정리한다.
- 브랜드나 서비스가 의도한 표기는 표준 표기와 달라도 유지한다.

### 문장

- 이중 피동을 단일 피동이나 능동으로 고친다: `판단되어진다→판단된다`, `보여지는→보이는`, `쓰여진→쓰인`.
- 피동형이 행위 주체를 가리면 원문에 드러난 주체를 살려 능동형으로 고친다. 주체가 없으면 새로 만들지 않는다.
- 군더더기 `있다`, `수 있는`, `것`, `적`, `의`, `들`은 빼도 뜻이 같을 때만 줄인다.
- 가벼운 동사를 구체 동사로 바꾼다: `회의를 가지다→회의를 열다`, `변경을 수행하다→변경하다`.
- 뜻이 분명하면 전치사 번역투를 자연스럽게 고친다: `계획에 대해 설명하다→계획을 설명하다`, `분석을 통해 확인하다→분석해 확인하다`.
- `에 있어`, `의 경우`, `로 인하여`, `와 관련하여`가 군더더기면 알맞은 조사나 어미로 줄인다.
- 불필요한 명사화를 동사로 바꾼다: `설정 변경을 진행한다→설정을 바꾼다`.
- 연결어미 뒤에 불필요하게 붙은 쉼표를 뺀다.
- 문장을 합치거나 나누지 않고 문장 안에서만 다듬는다.

### AI 문체

- 빈 도입을 바로 본론으로 고친다: `오늘날 빠르게 변화하는 시대에`, `바야흐로`, `이 글에서는 살펴본다`.
- 빈 맺음을 직접 서술로 고친다: `결론적으로`, `요약하면`, `시사하는 바가 크다`, `지금이야말로 ~할 때다`.
- 근거 없는 과장을 빼거나 원문에 있는 사실로만 바꾼다: `혁신적인`, `획기적인`, `압도적인`, `놀라운`, `매우 중요한`.
- 메타 멘트를 뺀다: `좋은 질문입니다`, `간단히 말하자면`, `다음과 같습니다`.
- 상투적인 강조 틀을 직접 서술로 바꾼다: `단순한 X가 아니라 Y`, `중요한 것은 X라는 점이다`.
- `또한`, `따라서`, `즉`이 없어도 흐름이 같으면 뺀다.
- `~라는 것이다`, `~라는 점이다`, `~라는 뜻이다`가 군더더기면 평서형으로 끝낸다.
- 막연한 출처를 사실처럼 바꾸지 않는다. 출처를 확인할 수 없으면 해당 주장을 유지한 채 표현만 보수적으로 다듬거나 원문을 둔다.
- 원문에 없는 수치·사례·감정·구어체를 만들어 자연스러움을 연출하지 않는다.

### 문체와 높임

- 원문의 해요체·합니다체·한다체를 유지하고 한 글 안의 불필요한 혼용만 고친다.
- 반말과 존댓말을 섞지 않는다.
- 사물에 붙은 과잉 높임을 고친다: `커피 나오셨습니다→커피 나왔습니다`, `품절이십니다→품절입니다`.
- 사람을 높이는 간접높임과 객체높임은 유지한다: `말씀이 있으시다`, `선생님께 드리다`.
- 공문·안내문은 쉬운 말로 고치되 법률·계약·전문 용어는 유지한다.

### 판단 기준

- 바꾼 뒤 뜻이 조금이라도 달라지면 원문으로 되돌린다.
- 깨끗한 문장은 고치지 않는다.
- 다양성을 만들려고 종결, 시제, 어휘를 억지로 바꾸지 않는다.

## 기본 모드

1. 대상과 보호할 문자열을 확인한다.
2. 공통 규칙을 한 번 적용해 확실한 문제만 국소적으로 고친다.
3. 다음 세 항목만 확인하고 결과를 원래 대상에 반영한다.
   - 보호 문자열이 그대로인가
   - 의미와 인과관계가 그대로인가
   - 장르와 높임 등급이 그대로인가

기본 모드는 직접 국소 교정과 보호 문자열·의미·인과관계·장르·높임 등급 검사만 사용한다.

기본 모드는 보호 문자열·의미·인과관계·장르·높임 등급이 유지되면 완료한다.

## 강한 모드

1. 대상과 보호할 문자열을 확인한다.
2. 공통 규칙과 `hard-rules.md`를 문장마다 적용한다.
3. 문단과 문서 전체에서 반복되는 접속사, 종결, 완곡 표현, 명사화, 영어 표현을 확인한다.
4. 잔존 문제나 보존 실패가 있을 때만 보수적으로 한 번 더 고친다.
5. 검증을 통과한 결과만 원래 대상에 반영한다.

### 일반 텍스트 파일

`.txt`와 `.md`처럼 본문이 중심인 파일은 OS 임시 디렉터리에 복사해 다음 도구를 사용한다.

```sh
mise exec -- python "$SKILL_DIR/scripts/segment.py" "$RUN_DIR/input.txt" --outdir "$RUN_DIR"
mise exec -- python "$SKILL_DIR/scripts/reassemble.py" "$RUN_DIR/segments.json" "$RUN_DIR/worksheet.md" --out "$RUN_DIR/result.txt"
```

- `worksheet.md`의 각 `윤문:` 줄에 한 문장만 채운다.
- 종료 코드 `2`면 누락·추가된 문장을 고친 뒤 다시 실행한다.
- 변경률이 `30%`를 넘으면 더 보수적으로 고친 뒤 다시 실행한다.
- 종료 코드 `3`이면 대상 파일을 수정하지 않는다.
- 검증을 마친 뒤 결과를 원래 대상에 반영하고 임시 디렉터리를 삭제한다.

### UI·소스 파일

사용자에게 보이는 한국어 문자열만 직접 고치고, 주변 코드와 구조가 달라지지 않았는지 확인한다.

강한 모드는 `hard-rules.md`의 강한 검증을 통과하고 잔존 문제와 보존 실패가 없을 때 완료한다.

## 결과 반환

- 붙여넣은 글이면 윤문본을 응답에 직접 제공한다.
- 파일을 고쳤으면 실제로 수정한 파일과 검증 결과만 짧게 알린다.
- 깨끗한 원문은 그대로 반환한다.
- 결과에는 윤문본 또는 실제 수정 파일과 검증 결과만 담는다.
