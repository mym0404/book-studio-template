# 표현 카탈로그 계약

루트 에이전트는 MDX 본문을 작성하기 전에 책 전체의 특별한 개념과 설명 방식을 조사해 하나의 표현 카탈로그로 잠근다. 카탈로그는 같은 원문 의미를 책 전체에서 같은 Markdown·MDX 문법으로 표현하는 단일 진실 공급원이다.

## 저장 위치

기본 경로는 `<output-root>/<book-slug>/work/representation-catalog.md`다. 책 일부만 처리하거나 작업을 재개할 가능성이 있으면 이 파일을 보존한다. 책 전체를 게시하고 전체 대조까지 통과한 뒤 정리할 수 있다.

## 사전 조사

1. Docling Markdown·JSON과 PDF 전체 페이지 썸네일에서 라벨, 시각적 박스, 캡션 패턴과 서체 변화를 찾는다.
2. PDF에서 각 후보의 첫 항목, 마지막 항목, 시각적 변형과 경계 사례를 원본 크기로 렌더링해 확인한다.
3. Red Flag, Warning, Note, Tip 같은 라벨 박스와 figure, 코드 목록, 수식, 사이드바, 연습 문제, 인용, 장 요약, 각주를 조사 후보로 삼는다.
4. PDF에서 실제 근거를 찾은 구조만 카탈로그에 등록하고 모든 출현 페이지를 기록한다.

## 카탈로그 형식

각 항목은 다음 값을 포함한다.

| ID | 원문 이름·표식 | PDF 페이지 | 의미와 시각적 특징 | 표준 MDX | 내용·배치 규칙 | 예외 |
| --- | --- | --- | --- | --- | --- | --- |

- `표준 MDX`에는 `.agents/knowledge/markdown-syntax.md`가 지원하는 완전한 문법 예시를 쓴다.
- 원문의 라벨, 제목, 본문, 캡션과 강조 범위가 MDX의 어느 부분에 대응하는지 적는다.
- 같은 의미와 시각적 역할을 가진 항목은 하나의 표준 표현을 공유한다.
- 의미나 역할이 다른 항목은 각각 별도 항목으로 유지한다.
- 예를 들어 PDF의 `Red Flag`가 경고 박스라면 실제 페이지 근거를 확인한 뒤 `<Callout type="warn" title="Red Flag: …">` 형식으로 잠글 수 있다.

## 변경 규칙

섹션 처리 중 새 특수 표현이나 기존 항목의 변형을 발견하면 해당 섹션을 보류하고 카탈로그에 PDF 근거와 표준 표현을 추가한다. 갱신한 항목이 적용될 수 있는 이전 페이지를 다시 검색하고 이미 만든 MDX를 같은 표준으로 맞춘 뒤 섹션 처리를 재개한다.

완료 조건: 모든 특수 표현이 PDF 출현 페이지, 의미, 표준 MDX와 배치 규칙에 연결되고, 각 결과 표현에 카탈로그 ID를 부여할 수 있어야 한다.
